# Fairfax County City Environment Explorer

A portfolio demo for exploring Fairfax County, VA air quality. It combines real
EPA AirNow PM2.5 monitoring data, an interactive map, time-series analysis,
location comparisons, and evidence-cited summaries generated by an Azure OpenAI
model. It is hosted on Azure Container Apps.

> **Data disclaimer:** Readings come from EPA AirNow monitoring sites and are
> provisional and unvalidated. They may be revised and are not a health or safety
> assessment. If no AirNow key is configured or AirNow is unavailable, the app
> falls back to clearly labeled synthetic sample data.

## Features

- Explore real PM2.5 monitoring sites in and around Fairfax County on a map.
- Filter hourly readings (averaged to local-day means) by site and time window.
- Compare site averages and inspect trends over time.
- Generate a grounded, Markdown-formatted summary with Azure OpenAI, citing
  evidence IDs. The citations are validated against the evidence supplied.
- Inspect source, time range, and summary statistics for each evidence record.

Without Azure credentials the summary button uses a deterministic fallback that
is labeled as not AI-generated. If Azure AI is configured but the request fails,
the application reports the error rather than silently substituting the fallback.

## Data source

Hourly PM2.5 comes from the
[AirNow API](https://docs.airnowapi.org/) monitoring-site service for a bounding
box around Fairfax County, with 30 days of history. Days with fewer than 18
hourly readings are dropped. The service can take 10 to 80 seconds, so a
background thread loads the data at container start and refreshes it hourly. The
last good snapshot is kept if a refresh fails. Users must follow the AirNow
[data use guidelines](https://docs.airnowapi.org/docs/DataUseGuidelines.pdf).

## Run locally

Requires Python 3.10 or newer.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python serve.py
```

The app is available at `http://localhost:8501`; set `PORT` to use another port.
`streamlit run app.py` also works. Set `AIRNOW_API_KEY` in `.env` for real data;
otherwise the app shows sample data. The map uses OpenStreetMap tiles and needs
an internet connection.

Run the focused tests with:

```powershell
pytest
```

## Optional Azure OpenAI summaries

1. Copy `.env.example` to `.env` and set `AZURE_OPENAI_ENDPOINT` to your Azure
   OpenAI resource root and `AZURE_OPENAI_DEPLOYMENT` to a deployed chat model.
2. For local development, sign in with Azure CLI and grant your identity the
   required model inference permission. The app uses `DefaultAzureCredential`.
3. Alternatively, set `AZURE_OPENAI_API_KEY` locally. Do not commit `.env` or
   credentials.
4. Restart the app and click **Generate summary**. Only the selected aggregate
   evidence records are sent to the configured model.

The Azure endpoint follows the OpenAI-compatible v1 API. Model usage may incur
charges. In an Azure-hosted production environment, use managed identity and set
`APP_ENV=production`; do not use a developer credential chain there. See the
[Microsoft Azure OpenAI Python endpoint guidance](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/switching-endpoints).

## Deploy to Azure Container Apps

The deployment uses Bicep and a GitHub Actions workflow with GitHub OIDC. It
creates a Basic Azure Container Registry, Log Analytics workspace, Container
Apps environment, and a publicly accessible HTTPS Container App. The app uses a
managed identity to pull its image; ACR admin credentials are disabled.

### One-time Azure setup

1. Create the Azure resource group in East US 2 (or another supported region).
   The workflow expects this resource group to exist.
2. Create an Entra application/service principal with a federated identity
   credential whose subject is
   `repo:silent-vector-26/city-environment-explorer:environment:azure-production` and whose
   audience is `api://AzureADTokenExchange`. Update the repository portion if
   the GitHub repository is renamed.
3. Grant that principal `Contributor`, `Role Based Access Control Administrator`,
   and `AcrPush` at the deployment resource-group scope. These roles let the
   workflow deploy resources, create the Container App's image-pull role
   assignment, and publish images. Use a dedicated deployment identity and
   review the permissions with your Azure administrator.
4. In GitHub, create the `azure-production` Environment. Configure required
   reviewers, prevent self-review if available, and restrict deployment
   branches to `main`. **The approval gate is enforced by GitHub Environment
   protection settings; the workflow pauses for approval only after those
   reviewers are configured.**
5. Add these **Environment variables** to `azure-production`:
   `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, and
   `AZURE_RESOURCE_GROUP`. `AZURE_LOCATION` is optional and defaults to
   `eastus2`. To enable Azure AI summaries, also set `AZURE_OPENAI_ENDPOINT`,
   `AZURE_OPENAI_DEPLOYMENT`, `AZURE_OPENAI_ACCOUNT_NAME` and
   `AZURE_OPENAI_RESOURCE_GROUP` (the existing account and its resource group).
   Add the AirNow key as the Environment **secret** `AIRNOW_API_KEY`. Do not put
   credentials or keys in workflow files or client-side code.
6. For Azure AI, also grant the deployment principal
   `Role Based Access Control Administrator` on the Azure OpenAI account. The
   template then grants the Container App's system-assigned identity the
   `Cognitive Services OpenAI User` role on that account.

### Deploy

The workflow at
[`deploy-azure-container-app.yml`](.github/workflows/deploy-azure-container-app.yml)
runs on pushes to `main` and can also be started with **Actions → Deploy Azure
Container App → Run workflow**. It first runs tests and builds the container.
After those checks pass, the deployment job waits for approval in
`azure-production`, then provisions the infrastructure, builds and pushes the
container image, deploys the app, and prints its HTTPS endpoint.

The Bicep template is [`infra/main.bicep`](infra/main.bicep), with a small module
for the Azure OpenAI role assignment. It keeps one replica running (`minReplicas`
is 1) so the in-memory AirNow cache stays warm; this means the app has a
continuous compute cost. Setting it to 0 allows scale-to-zero but causes slow
cold starts. Container Apps, registry storage, and log ingestion can incur
charges. Review current pricing and configure budget alerts.
